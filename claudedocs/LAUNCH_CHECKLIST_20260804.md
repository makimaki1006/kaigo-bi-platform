## 1. 事業者情報（ご本人）

`kaigo-bi-frontend/src/lib/legal.ts` の以下を埋める。
**現在すべて `（未設定）`** で、埋まるまで法務3ページは自動的に noindex。

| 項目 | 用途 | 備考 |
|---|---|---|
| `name` | 事業者名 | 法人名または屋号 |
| `representative` | 運営責任者名 | 特商法で必須 |
| `address` | 所在地 | 特商法で必須。番地まで |
| `phone` | 電話番号 | 特商法で必須。「請求があれば遅滞なく開示」の運用も可 |
| `contactEmail` | 問い合わせ先 | — |
| `privacyContact` | 個人情報の窓口 | `contactEmail` と同じで可 |
| `court` | 専属的合意管轄裁判所 | 通常は所在地を管轄する地方裁判所 |

> **個人事業主の場合**: 特商法上、原則として氏名・住所・電話番号の表示が必要。
> バーチャルオフィス等の利用可否を含め、専門家に確認することを勧める。

## 3. 独自ドメイン（ご本人＋私）

### ご本人の作業
1. ドメインを取得（例: `kaigo-bi.jp` / `kaigo-bi.com`）
2. Render のダッシュボードで Custom Domain を追加
3. 表示された CNAME / A レコードをドメイン管理画面に設定

### 私の作業
`NEXT_PUBLIC_SITE_URL` を設定すれば、canonical / OG / sitemap が自動的に追随する。
`src/lib/site.ts` で一元管理しているため、コード側の変更は不要。

```
Render の Environment に追加:
  NEXT_PUBLIC_SITE_URL = https://（新ドメイン）
```

設定後、次を検証する。
- `sitemap.xml` の URL が新ドメインになっているか
- 各ページの canonical が新ドメインを指しているか
- 旧ドメイン（`kaigo-bi.onrender.com`）からのリダイレクト

> 現状は `NEXT_PUBLIC_SITE_URL` 未設定で、本番では
> `https://kaigo-bi.onrender.com` にフォールバックしている（`IS_SITE_URL_FALLBACK = true`）。

## 4. Stripe 本番キー（ご本人＋私）

### ご本人の作業
1. Stripe ダッシュボードで本番モードを有効化（事業者情報・銀行口座の登録、審査）
2. 本番の Secret Key を取得
3. 本番モードで各プランの Price を作成し、Price ID を控える

### 私の作業
Render の環境変数に設定し、決済フローを検証する。

```
STRIPE_SECRET_KEY          = sk_live_...
STRIPE_PRICE_STANDARD      = price_...
STRIPE_PRICE_PRO           = price_...
STRIPE_PRICE_MA            = price_...
STRIPE_WEBHOOK_SECRET      = whsec_...
```

Webhook のエンドポイントも本番URLで登録し直す必要がある。

> **テストモードのまま公開すると決済が完了しない。** 課金開始前に必ず切り替える。

## 5. Resend ドメイン認証（私＋ご本人）

現状は Resend の共有ドメインから送信していると思われ、
**パスワード再設定メールが迷惑メール判定される可能性がある**。

### 手順
1. Resend で独自ドメインを追加
2. 表示される SPF / DKIM / DMARC レコードをDNSに設定（私が提示、ご本人が登録）
3. 認証完了後、送信元アドレスを `noreply@（独自ドメイン）` に変更

---

## 6. Search Console（ご本人）

独自ドメイン設定後に実施する。

1. Google Search Console でプロパティを追加
2. DNS TXT レコードで所有権を確認

> ドメイン変更前に登録すると、移行時に再登録が必要になる。**③の後に実施すること。**
