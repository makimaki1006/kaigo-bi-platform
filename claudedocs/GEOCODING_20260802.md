# 施設ジオコーディングと周辺施設マップ（2026-08-02）

## 背景

`facilities` は116カラムあるが**緯度経度が1つもなく**、`/market` の施設分布マップは常に空表示だった。
「選んだ施設を中心に周辺施設を可視化する」機能を作るには座標が必須。

## Google を使わなかった理由

当初 Google Places / Geocoding API が候補に挙がったが、次の理由で採用しなかった。

### 精度差がない
国土地理院のジオコーディングAPIを10都道府県10件で試したところ**10/10成功**、番地レベルまで一致した。

```
北海道札幌市中央区南14条西1丁目2-22  -> 43.04192, 141.35661
沖縄県那覇市高良3-8-23              -> 26.18930, 127.65936
```

### コスト
Google Geocoding API は22万件で概算 **$1,100前後**（$5/1,000件・要最新料金確認）。公的データなら0円。

### 規約の非互換
現行の地図は **Leaflet + OpenStreetMap タイル**。Google Maps Platform 利用規約は
「Google Maps Content を Google マップ以外の地図上に表示すること」を禁じている。
Google の座標を使うなら地図コンポーネントごと Google Maps に載せ替える必要があり、API差し替えでは済まない。

### 口コミについて（別途検討した結果）
Places API のレビューは **1施設あたり最大5件**しか返らず、かつ Google Maps Content は
キャッシュ・保存が原則禁止（Place ID のみ例外）。
**口コミをDBに蓄積して有料SaaSで提供するモデルは成立しない**と判断した。

規約内で成立する形は「施設詳細に Google Maps を埋め込み、口コミは Google のUI内で見せる。自社では保存も分析もしない」。

> 料金・規約は改定されるため、最終判断の前に Google Maps Platform の公式規約を確認すること。
> 上記は2026年5月時点の知識に基づく。

## 採用したデータ源

**国土交通省「位置参照情報（大字・町丁目レベル）」** — https://nlftp.mlit.go.jp/isj/

| 項目 | 内容 |
|------|------|
| 費用 | 無料（APIキー不要） |
| ライセンス | 出典表示のみで商用利用可 |
| 粒度 | 町丁目レベル（190,926エントリ） |
| 取得量 | 47ファイル / 約3.2MB |

**精度の限界**: 同一町丁目の施設は同じ座標になる（突合結果 203,499 行がユニーク 58,186 座標に集約）。
「周辺に何があるか」には十分だが、番地単位の正確な位置が要る用途には使えない。画面にもその旨を明記した。

## 突合の実装

`scripts/geocode_facilities.py`

住所データの表記が想像以上に不揃いで、素朴な突合では **78.5%** にとどまった。
失敗パターンを潰して突合結果を 203,499 行まで引き上げた。
※ この 203,499 は突合CSVの行数（ユニーク事業所番号 174,080）であり、
DB に反映すると **205,056 行 = 91.9%** に座標が付く。
事業所番号は1事業所×1サービスで重複するため、CSV 1行が複数行を更新するため。

### 実データにあった表記の揺れ

| パターン | 例 | 対処 |
|---|---|---|
| 郵便番号の位置が不定 | `北海道〒064-0914 札幌市…` / `〒064-0806 北海道札幌市…` | 郵便番号を除去し都道府県を再判定 |
| 丁目の省略 | `南16条西7-2-20`（正: 南十六条西七丁目） | 町名直後の数字を丁目とみなす候補を追加 |
| 漢数字 vs アラビア数字 | DB `南14条` / ISJ `南十四条` | 丁目・条・線を漢数字へ変換 |
| ISJ側が大字付き | ISJ `大字中判田` / DB `中判田` | 大字あり・なし両方の候補を出す |
| 字以下がISJにない | `渡利字中江町`（ISJは `渡利`） | 「字」以降を落とした候補を追加 |
| 字符号 | `田中町は16番地`（ISJは `田中町`） | 末尾1文字のかな・甲乙丙丁を落とす |
| 区名の欠落 | `札幌市北28条西3丁目`（正: 札幌市北区…） | (都道府県, 町丁目) で逆引き |
| 都道府県の欠落 | `札幌市手稲区金山1条2丁目`（約3,000件） | (市区町村, 町丁目) で逆引き |

### 突合結果

| 手法 | 件数 | 割合 |
|---|---:|---:|
| 完全一致 | 192,334 | 86.2% |
| (都道府県,町丁目) 逆引き | 6,352 | 2.8% |
| 異体字正規化 | 2,447 | 1.1% |
| (市区町村,町丁目) 逆引き | 2,359 | 1.1% |
| 区の絞り込み | 7 | 0.0% |
| **未突合** | **19,604** | **8.8%** |

**逆引きが複数候補に割れた場合は採用しない**方針にした。誤った区に施設を置くより、座標なしのまま残す方が安全なため。

検証: 突合結果 203,499 行すべてが日本の緯度経度範囲内（緯度24.34〜45.42 / 経度123.83〜145.66）、範囲外0件。

### 未突合 8.8% について
残るのは北海道の郡部・字・線を含む住所や、住所自体が壊れているもの（`旭川市東光旭川市東光11条5丁目` のような二重記載）。
必要なら国土地理院APIで補完可能（19,604件・逐次実行で数時間）。現状は座標 null のままにしてある。

## 実装した機能

### バックエンド

`GET /api/facilities/nearby?center=<事業所番号>&radius_km=3&<既存フィルタ>`

1. 中心施設の座標を取得
2. 緯度経度の**矩形**でSQL絞り込み（緯度1度≒111km、経度は cos 補正）
3. **Haversine** で実距離を計算し半径内に厳密化
4. 距離昇順でソート

レスポンスに `matched`（半径内の総数）と `truncated` を含め、上限で切った場合に画面が明示できるようにした。

`GET /api/facilities/search` も `latitude` / `longitude` を返すようにした。

### 事業所番号の重複（投入後に判明）

投入完了時の検証で、CSVの203,499件に対しDBの座標付与が204,907件と多かった。
調べたところ **`facilities` は「1事業所 × 1サービス」で1行**の構造で、
同じ事業所番号が最大8行あった（223,103行 / ユニーク190,003件 = **33,100件の重複**）。

例（事業所番号 1452880029、8行）:
訪問介護 / 訪問リハビリテーション / 通所リハビリテーション / 短期入所療養介護_老健 / 居宅介護支援 / 介護老人保健施設 …

集約しないと**同じ施設が地図に複数ピン、一覧に複数行**出てしまうため、
`facilities_nearby` で事業所番号ごとに集約した。

| 項目 | 集約方法 |
|---|---|
| サービス名 | 重複を除いて配列 `service_names` に |
| 従業者数・定員 | サービスごとの計上なので**合算** |
| 離職率 | 妥当な値がある行だけで平均 |

実測（ゆめかケア 神保町本店・東京都、半径3km）: 矩形489行 → **321事業所**（距離昇順）。

### フロントエンド

新規ページ **`/facility-map`**（サイドバー「市場を知る」に追加）

- 施設名・法人名・電話番号で中心施設を検索して選択
- 半径 1 / 3 / 5 / 10 / 20 / 30 km
- フィルタ: 法人種別・サービス種別（部分一致）・従業者数の下限
- 地図: 中心ピンをオレンジで強調、半径円を描画、半径に応じて自動ズーム
- 周辺のサービス構成（何が多いエリアか）
- 距離昇順の一覧（200行まで、超過時は件数を明示）

`FacilityMap` / `FacilityMapInner` に `center` / `radiusKm` を追加。中心指定時は周辺0件でも地図を表示する。

## 運用手順

```bash
# 位置参照情報を取得（初回のみ、約3MB）
python scripts/geocode_facilities.py --download

# 突合してCSV出力（DBは変更しない）
python scripts/geocode_facilities.py --match

# Tursoへ反映（latitude/longitude カラムを作成して更新）
python scripts/geocode_facilities.py --apply
```

環境変数 `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` が必要。
スクレイピングでデータを更新した後は `--match` → `--apply` を再実行する。

## 今後の選択肢

- **未突合 8.8% の補完**: 国土地理院APIで逐次補完（無料・数時間）
- **番地レベルの精度が要る場合**: 国交省「街区レベル位置参照情報」への切り替え
- **不動産評価**: 国土交通省「不動産情報ライブラリ」API（APIキー申請制・無料）で取引価格・地価公示が取れる。M&A/事業承継層向けの土地建物評価に直結
- **Google Maps 埋め込み**: 口コミを規約内で見せたい場合の唯一の現実的な形
