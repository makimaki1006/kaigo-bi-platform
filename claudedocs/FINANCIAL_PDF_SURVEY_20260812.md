# 決算PDFの実測調査と、アプリへの組み込み方針（2026-08-12）

`C:\Users\fuji1\kaigo-bi-platform\claudedocs\FINANCIAL_PDF_SURVEY_20260812.md`

介護サービス情報公表システムに掲載されている決算書を実際に取得して中身を調べ、
**何なら全施設分を項目化できて、何はできないか**を切り分けた記録。
結論と、それに基づいて入れた実装、集計案までをまとめる。

## 0. 結論（先に）

| 層 | 中身 | 網羅性 | 扱い |
|---|---|---|---|
| **Tier 1** | 決算書の**開示状況**（有無・3点セット・掲載日・形式・会計種類） | **全223,103施設で確定** | 項目化して集計・可視化した |
| **Tier 2** | 決算書の**金額**（収益・人件費・総資産 等） | **取れて約25%**、しかも偏る | 取れた分だけ、来歴付きで個別表示 |
| **Tier 3** | スキャン画像・非標準様式の中身 | 不能 | 備考＋原本リンク |

**金額は網羅的な指標にできない。** これが調査の主結論。
理由は「まだ解析していないから」ではなく、**元データが自由書式のアップロードだから**で、
解析器を強化しても越えられない上限がある（後述の実測値）。

一方で「決算書を出しているか・いつ出したか」は100%機械的に決まり、
これは今までアプリで使っていなかった。ここを新しく指標にした。

### テキスト層の有無 = 機械抽出の可否そのもの

**全体 47.5%（246/518）しかテキスト層がない。** 残りはスキャン画像。

| 社会福祉法人 | 82 | 63.4% |
| NPO法人 | 61 | 57.4% |
| 社会医療法人 | 30 | 46.7% |
| 医療法人 | 76 | 44.7% |
| その他法人 | 47 | 42.6% |
| 株式会社・有限会社等 | 107 | **37.4%** |
| 社団法人 | 34 | **29.4%** |

会計種類別では 社会福祉法人会計基準 65.9% が最も高く、
老健準則 32.1%、記載なし 42.2%。

### 様式がまったく統一されていない

| 様式（本文の見出しから判定） | 出現率 |
|---|---:|
| 貸借対照表 | 34.6% |
| 損益計算書 | 19.1% |
| 活動計算書 | 14.6% |
| 事業活動計算書 | 9.3% |
| 収支計算書 | 8.1% |
| キャッシュフロー計算書 | 7.7% |
| 資金収支計算書 | 7.3% |
| 正味財産増減計算書 | 2.4% |

「事業活動計算書」としてアップロードされたファイルの中身が損益計算書だったり、
1つのPDFにPL・BS・財産目録が全部入っていたりする。**ファイル名と中身が対応しない。**

さらに実物には以下が混在する:

- 正規の財務諸表（社福会計基準 第二号第四様式 等）
- **会計ソフトの合計残高試算表**（列が「前残高/借方/貸方/残高/構成比」）
- TKCの「事業別科目残高」出力（列順が独自）
- 予算対比表（列が「予算/決算/差異」）
- 地方公共団体の行政コスト計算書

列の意味が様式ごとに違うため、「1列目が当年度」といった固定ルールが通らない。
解析器は見出し語のx座標を取って数値を列に割り当てる方式にした。

### 手入力・OCRの誤字が実在する

実際に見つかった例（`0170105449_PL.pdf`）:

```
I売上貴          ← 売上高
計上損失         ← 経常損失
税引前冬期純損失  ← 税引前当期純損失
```

縦書きの見出し（「医業収益」を縦に組んだもの）が隣の行に食い込み、
`医居宅介護支援事業収入` のようなラベルになる例も確認した。

**ここが「解析器を強化すれば網羅できる」とは言えない根拠。**
辞書を増やしても、誤字のパターンは事業者ごとに無限にある。

### 会計期間と単位が分からないものが多い

| 項目 | 特定できた率（テキスト層あり中） |
|---|---:|
| 会計期間（自〜至） | **20.7%** |
| 単位（円/千円/百万円） | 84.6%（円66.3% / 千円17.1% / 百万円1.2%） |
| 集計単位（法人全体か拠点か） | **24.4%**（記載なしが75.6%） |

年度が分からない金額は時系列比較に使えない。
単位が分からないと1000倍ずれる。
法人全体か1拠点かが分からないと、施設間で横に並べられない。

## 4. 金額はどこまで取れたか

分母はそのdoc_typeの全ファイル（229 PL / 206 BS / 83 CF）。

| 項目 | 全体比 | テキスト層あり比 |
|---|---:|---:|
| 当期純利益・当期活動増減差額 | 23.1% | 50.5% |
| 収益合計 | 20.5% | 44.8% |
| 人件費 | 18.8% | 41.0% |
| 経常利益 | 18.8% | 41.0% |
| 営業利益・サービス活動増減差額 | 16.6% | 36.2% |
| 純資産（BS） | 25.2% | 55.3% |
| 負債合計（BS） | 18.4% | 40.4% |
| 総資産（BS） | 13.1% | 28.7% |

### 使えるレコードの歩留まり

```
PL 収益が取れた              57/229 = 24.9%
PL 収益 + 人件費が取れた      30/229 = 13.1%
BS 総資産 + 純資産が取れた    23/206 = 11.2%
```

### rule_v2 での改善（2段組の貸借対照表への対応）

未マッチのラベルを集計したところ `資産の部合計負債純資産の部合計` `流動資産流動負債`
といった**2つのラベルが結合した文字列**が頻出していた。
貸借対照表は「資産の部｜負債・純資産の部」の2段組が多く、
y座標で行をまとめると左右の表が1行に結合されてラベルが一致しなくなっていた。

対策を2つ入れた。

1. ページ中央で左右に分割してから行を組み直す（`page_rows_split`）
2. **分割した表ごとに列見出しを判定する** — 左右まとめて列を判定すると、
   右表の数値が左表の「当年度」列に割り当たって値がずれる

2つ目が重要で、1つ目だけだと検算一致率が 87.0% → 67.3% に落ちた。
表ごとに判定して 90.4% まで回復し、v1より良くなった。

| 指標 | rule_v1 | rule_v2 |
|---|---:|---:|
| BS 総資産 + 純資産が取れた | 11.2% | **27.2%** |
| BS 総資産 | 13.1% | **31.6%** |
| BS 負債合計 | 18.4% | **35.9%** |
| PL 収益 | 24.9% | **28.4%** |
| 検算（資産=負債+純資産）の一致 | 87.0% | **90.4%** |
| 検算に通った実数 | 20件 | **47件** |

### 本番バッチ（法人単位で重複排除・11,694ファイル / 5,148施設）で測り直した値

サンプルは層化のため高歩留まりの法人種別（社福・財団・NPO）を厚く取っている。
実際の母集団に近い値はこちら。**サンプルより低い。**

| 指標 | 層化サンプル(518) | 本番バッチ(11,694) |
|---|---:|---:|
| テキスト層あり | 47.5% | **42.9%** |
| PL 収益が取れた | 24.9% | **20.7%** |
| PL 収益 + 人件費 | 13.1% | **5.7%** |
| BS 総資産 + 純資産 | 11.2% | **7.1%** |
| 恒等式（資産=負債+純資産）の一致 | 87.0% | **85.6%** |
| 会計期間を特定（テキスト層あり中） | 20.7% | **10.9%** |
| 集計単位の記載（テキスト層あり中） | 24.4% | **19.4%** |
| 単位の明記（テキスト層あり中） | 84.6% | **81.4%** |

この数値は固定値ではなく `financials` テーブルから毎回算出している
（`aggregate_financial_disclosure.py` の [7/7]）。抽出器を改善すれば自動で更新される。

法人種別で大きく偏る:

| 法人種別 | PL収益の取得率 |
|---|---:|
| 財団法人 | 57.1% |
| NPO法人 | 51.7% |
| 社会福祉法人 | 28.6% |
| その他法人 | 22.2% |
| 株式会社・有限会社等 | 20.8% |
| 医療法人 | 10.3% |
| 社会医療法人 | **0%** |

**この偏りが致命的。** 「抽出できた施設の平均人件費率」を出すと、
NPOと財団に寄った数字になり、業界平均としては使えない。

### 取れた値は正しいのか

恒等式チェック（資産 = 負債 + 純資産）:

```
3項目そろった   23/206 = 11.2%
うち一致        20/23  = 87.0%   ← 抽出値の信頼性
不一致          3
```

PL（収益 − 費用 = 利益）は 10件中6件一致（60.0%）。
PLの方が低いのは、営業外・特別損益を挟むため単純な引き算にならない様式があるため。

**取れたときの値は概ね正しいが、取れる確率が低い**、というのが実態。

### 5-2b. 目視で見つかった不具合2件（修正済み）

本番で `?id=3571501950`（&Lifeケアプランセンター / 株式会社維新）を開いても
決算系が何も出ない、という指摘から2つの実装バグが出た。

**① 金額が取れていない施設で「何も表示されない」**

`financials` にレコードがあることを「金額がある」と扱っていたため、
- ページ側は「金額あり」と判定して財務サマリーを描こうとする
- ところがサマリーは PL / BS しか見ないので、CFだけ値があると何も描かない
- 結果、カードも「取れなかった理由」も出ない**無表示**になる

対応: 判定を **PL / BS のレコードに値があるか**へ統一（フロント・バックエンド両方）。
`financial_status` に `parsed_no_amount`（解析したが金額が読めない）を追加し、
理由と原本リンクを出す分岐を用意した。

**② 資金収支計算書の「当期収支差額」を当期純利益として入れていた**

同施設のCFに `net_income = 6,000` が入っていた。
資金収支計算書の当期収支差額は**資金の増減**であって損益ではない。
利益として表示すると誤読につながる。

対応: CF書類のときだけ、収支差額由来の `net_income` を落とす
（収支計算書をPL代わりに使う小規模法人があるため、CF以外では残す）。
`EXTRACTOR_VERSION` を `rule_v3` に上げ、旧バージョンのレコードは再処理される。

## 6. 集計案

### 実装済み（Tier 1・母集団が全数なので集計して良い）

| 集計 | 使いどころ |
|---|---|
| 都道府県 × 開示率 | 地域ごとのデータ取得可能性。営業リストの精度見積り |

### AI視覚抽出について

規則ベースの上限は上で測ったとおり。これを超えるには
スキャン画像をAIに読ませるしかない（既存の24法人がその方式）。

概算: 対象は法人単位で約68,563法人 × PL/BS 2枚 = 約137,000ページ。
仮に1ページ0.01ドルなら約1,370ドル。**やるなら費用対効果を先に決めること。**

ただしAIで読んでも「集計単位が書いていない」「会計期間が書いていない」問題は残る。
金額が読めても、法人全体か1拠点かが分からなければ横比較はできない。
**AI抽出は歩留まりを上げるが、比較可能性の問題は解決しない。**

## 6-b. 長時間バッチの運用（実際に落ちた）

`fin_extract_batch.py` は10万ファイル規模で**約3時間**かかる。
2026-08-12 の実行では 7,000件（7%）の時点で止まった。
原因は**ノートPCを閉じたこと**（スリープでプロセスが落ちる）。

対策として入れたもの:

| 対策 | 内容 |
|---|---|
| 逐次書き込み | 2,000件ごとに `financials` へ流す。落ちてもそこまでは残る |
| バージョン単位のスキップ | `EXTRACTOR_VERSION` と一致するレコードだけスキップ。旧版は作り直す |
| アイドルスリープ抑止 | `SetThreadExecutionState(ES_SYSTEM_REQUIRED)` を実行中だけ有効化 |

> ⚠️ **ノートを閉じたときのスリープはスクリプト側から抑止できない**（電源設定の動作）。
> 落ちたら同じコマンドを再実行すれば、済んだ分はスキップして続きから走る。

```powershell
python scripts/fin_extract_batch.py --limit 0 --parallel 6   # 何度実行しても安全
```

## 9. 注意点

- `financial_extraction_status` は `financials` の実データから毎回算出する。
  抽出器を変えたら `aggregate_financial_disclosure.py` を回し直すだけでよい。
- 金額の全国平均・順位付けは作らないこと。母集団が法人種別に大きく偏る。
- `unit_source != "pdf"` のレコードを比率計算に使わないこと。1000倍ずれる。
- 決算書の中身が介護事業とは限らない（地方公共団体の行政コスト計算書、病院の医業収益など）。
  法人全体の決算に介護以外が混ざる。
