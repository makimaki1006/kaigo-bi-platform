# facilitiesテーブル(112カラム)フル活用監査 (2026-07-24)

方法: 全112カラムの充足率(223,103行の非空集計)× バックエンド/ETLの参照状況を突合し、
「持っているのに使っていない情報」と「集計にしか使わず個別画面に届いていない情報」を多角的に洗い出した。
生データ: scratchpad/column_audit.md(充足率×参照箇所の全表)

## 結論(1行)

**カラム単位の未参照は27個だが、本質的な問題は「使用中カラムの大半が全国集計チャートで消費され、
施設・法人の個別意思決定画面には112カラム中30カラムしか届いていない」こと。**

## 発見1: 施設詳細APIが「本体データの27%」しか返していない(最重要・工数小)

`facility_detail` のSELECTは30カラムのみ。一方フロントの`FacilityDetailPanel`は
要介護度分布・加算バッジ・品質スコア・ランク・ICT/BCP/第三者評価の表示に**既に対応済み**なのに、
APIがデータを渡していないため永遠に空欄。以下を返すだけで詳細ページが一変する:

| 未配信カラム群 | 充足率 | 使い道 |
|---|---|---|
| 要介護1〜5・利用者総数 | 74〜89% | 利用者の重度構成(=単価・ケア負荷の推定) |
| 職種別人員18列(介護/看護/相談員/機能訓練/栄養士/事務) | 40〜52% | 人員配置の厚み、看護配置=医療対応力 |
| 資格4列(介護福祉士66%等)・夜勤/宿直 | 21〜66% | 人材の質、夜間体制 |
| 品質4列+quality_score/rank(復元済み) | 9〜97% | 品質バッジ(UI実装済み) |
| 経験10年以上割合 | 66% | 定着力の代理指標 |
| 利用者_都道府県平均 | 81% | 「県平均比」の即席ベンチマーク |
| スクレイピング日 | 100% | データ鮮度の明示(信頼性UX) |

## 発見2: 行政処分・指導データが完全放置、DDは`has_violations: false`のハードコード(M&Aの信頼性問題)

行政処分1,213件・行政指導671件を保有しているのに未参照。しかもDDレポートは
コンプライアンス違反を**常にfalse**で返している。M&Aツールとして最も見られる項目の一つが
「実データがあるのに固定値」— これは早急に接続すべき(工数小)。施設詳細・法人詳細・
M&Aスクリーニングの除外条件にも展開可能。

## 発見3: `加算_全項目`(94%充足)が個別加算カラムの穴を埋める鍵

個別の加算フラグ13列は充足2〜29%と貧弱(特定サービス種別しか取れていない)が、
`加算_全項目`は208,762件(94%)にフル加算リストのテキストを保持している。
これをパースして個別フラグへ展開すれば、処遇改善・特定事業所などの加算分析が
「一部サービスの参考値」から「全国網羅データ」に格上げされる。
(処遇改善加算=人件費原資なので、経営支援・採用コンサル両方の核指標)

## 発見4: 「県平均」止まりで市区町村の解像度が無い

充足100%の`都道府県コード`はあるが市区町村コードが無く、住所からの市区町村結合も未実装。
外部DBの市区町村資産(採用スコア20,845行・人口・人流)と繋ぐには
**住所→市区町村コードのジオコーディング1本**が必要(external DBに`municipality_code_master`保有済み)。
これが繋がると「施設×商圏人口×採用難易度」の面分析が解禁される。

## 発見5: 低充足だが価値のあるロングテール
